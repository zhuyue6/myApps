# 目标打卡管理后台 · 方案设计

版本：v0.1 草案  
范围：登录、用户管理，以及 Vue 3 + Element Plus + TypeScript 前端框架  
状态：待确认。确认前不编写业务代码，不生成 `prototype/` 画面文件。

## 1. 这份文档要定什么

管理后台是给运营看的桌面网页，和小程序是两个端，共用同一套打卡业务数据。

本期只做两件事：

1. 管理员登录、退出。
2. 查看并停用 / 启用小程序用户。

同时把前端工程骨架定下来，后面加「打卡计划」「标签」时只加页面，不改技术选型。

确认本文后，下一步才是：把下面四张画面做成 `prototype/` 里的桌面原型图，再初始化 Vue 工程。

## 2. 依据：现在的小程序在管什么

小程序底部三个 Tab：打卡、标签、我的。未登录会进入独立登录页。

用户在小程序里能做的事：

| 对象 | 用户能做的 | 关键字段 |
| --- | --- | --- |
| 账号 | 注册、登录、退出、上传头像 | `id`、`userName`、`password`、`sex`（1 男 / 2 女 / 3 保密）、`age`、`avatarUrl`、`token` |
| 打卡计划 | 新增、编辑、删除、打卡 | 名称 `remark`、截止时间 `expirationTime`、周期 `clockInCycle`（1 日 / 2 周 / 3 月）、目标次数（服务端按周期和截止时间计算）、已打卡次数、状态（1 进行中 / 2 已完成 / 3 已过期）、可选标签 |
| 标签 | 新增、删除。修改接口当前未开放 | `labelName`、`labelType`。同一类型下名称不可重复 |

接口形态已经固定，管理端沿用，避免两套协议：

- 基址开发环境 `http://127.0.0.1:9090`，现网小程序另有 `http://114.55.136.107/api`。
- 响应体 `{ code, message, data }`，`code === 0` 为成功。
- 登录态用 `Authorization: Bearer <token>`。
- 未登录或登录失效：HTTP 401，或业务码 `10006` / `10007`。

现有接口都是「当前登录用户」视角：`/user/login`、`/goal/getGoals`、`/label/getLabelList` 只返回本人数据。管理后台需要单独的管理员接口，不能复用这些接口去翻别的用户。

## 3. 后台定位

| 项 | 决定 |
| --- | --- |
| 使用的人 | 内部管理员。小程序用户不能从登录页注册成管理员 |
| 账号 | 与小程序用户分表。管理员有自己的用户名、密码、显示名 |
| 本期能做的 | 登录、退出、按条件查用户、看用户详情、停用或启用用户 |
| 本期不做的 | 注册管理员、改小程序用户资料、重置用户密码、代用户打卡、管理计划、管理标签、数据看板、内容审核 |

停用后的效果：该用户不能再登录小程序，已发出的 token 失效。启用后恢复登录。计划、标签、打卡记录保留，不删除。

首个管理员由后端初始化写入，账号不写进前端仓库。

## 4. 信息架构

登录成功后进入左侧菜单 + 顶栏的后台壳。本期菜单只有「用户管理」。壳上预留后续菜单的位置，但本期不出现灰色占位项，避免点进去是空页。

```

        │
        ▼
后台壳
├─ 顶栏：产品名「目标打卡管理」、当前管理员、退出
```

后续可加、本期不建页面：概览、打卡计划、标签。路由和目录按这个扩展来留。

- 头像、用户名、用户 ID
- 性别、年龄

打卡概况（只读，帮管理员判断要不要停用）：

### 6.3 路由与登录守卫

| 路径 | 页面 | 是否要登录 |
| --- | --- | --- |
| `/login` | 登录 | 否。已登录则去 `/users` |
| `/users` | 用户列表 | 是 |
| `/` | 重定向到 `/users` | 是 |
| 其他 | 重定向到 `/users` | 是 |

token 存在 `localStorage`，键名 `cmg_admin_token`，与小程序的 `clock_in_token` 分开。管理员显示名存在同一次登录响应里，键名 `cmg_admin_profile`。

守卫：目标路由需要登录且本地没有 token 时，跳到 `/login?redirect=<原路径>`。登录成功后回到 `redirect`，没有则去 `/users`。

接口返回 HTTP 401，或业务码 `10006` / `10007` 时：清掉本地登录态，若当前不在登录页则带上当前路径跳到登录页。

### 6.4 请求约定

`src/api/http.ts` 做这些事：

1. `baseURL` 读 `import.meta.env.VITE_API_BASE`。
2. 有 token 时加 `Authorization: Bearer <token>`。
3. 响应 `code === 0` 时把 `data` 交给调用方。
4. 其他 `code` 抛出带 `message` 的错误，由页面用 `ElMessage` 提示。
5. 网络失败提示「网络异常，请稍后重试」。

开发环境 Vite 把 `/api` 代理到 `http://127.0.0.1:9090`，并去掉前缀 `/api`，这样浏览器请求 `/api/admin/login`，后端收到 `/admin/login`。

### 6.5 本期前端依赖的接口

这些接口本期后端尚未在本仓库实现。前端按下面的契约开发；字段若与后端最终表结构不一致，以确认后的契约为准改类型，不改页面结构。

通用响应：`{ code: number, message: string, data: T }`。

**POST `/admin/login`**

请求：`{ userName: string, password: string }`

成功 `data`：

```ts
{
  token: string
  id: number
  userName: string
  displayName: string
}
```

失败：账号或密码错误时 `code !== 0`，`message` 给用户看。密码不明文回传。

**POST `/admin/logout`**

需登录。成功后前端无论接口成败都清除本地 token，再进入登录页。

**GET `/admin/users`**

查询参数：`keyword`、`status`（不传表示全部；`1` 正常，`0` 停用）、`page`（从 1 开始）、`pageSize`。

成功 `data`：

```ts
{
  total: number
  list: Array<{
    id: number
    userName: string
    sex: 1 | 2 | 3
    age: number | null
    avatarUrl: string
    status: 0 | 1
    createdAt: string
  }>
}
```

**GET `/admin/users/:id`**

成功 `data` 在列表字段之外增加：

```ts
{
  ongoing: number
  completed: number
  expired: number
  labelCount: number
  plans: Array<{
    id: number
    name: string
    cycle: 1 | 2 | 3
    checkedCount: number
    targetCount: number
    status: 1 | 2 | 3
    deadline: string
    createdAt: string
  }>
}
```

`plans` 最多 10 条。

**POST `/admin/users/:id/status`**

请求：`{ status: 0 | 1 }`。`0` 停用，`1` 启用。

成功 `data` 返回更新后的用户列表项。停用要让该用户已有小程序 token 失效。

列表和详情都不返回密码。

## 7. 页面状态（前端自己掌握）

登录页：`userName`、`password`、字段错误、提交中。

用户列表：筛选草稿、已生效筛选、`page`、`pageSize`、`total`、`list`、加载中、详情抽屉的 `userId`、确认框的目标和动作（停用或启用）。

用户详情：跟随 `userId` 拉取。切换用户或关闭抽屉时丢弃过期响应，避免慢请求覆盖新用户。
